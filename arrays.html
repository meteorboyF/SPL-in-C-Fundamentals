Arrays

An array is a row of boxes in memory, all of the same type, numbered from 0. Almost every LeetCode problem is about arrays. Each visualiser here has an Arrays tab that draws the arrays with large cells:

  • index variables (i, l, r, low, high …) are drawn as pointers under the cell they point to, and the range between them is shaded;
  • cells are blue when read and yellow when written;
  • 2D arrays get a row/column crosshair, 3D and higher get one slice per layer;
  • a bar chart mode and a memory layout view with the address formula;
  • maps and sets are drawn as tables and chips.

Out of bounds
C does not check indices. a[5] on a 5-element array reads or writes whatever memory comes next: garbage values, crashes, or bugs that appear randomly. The visualiser stops with an error instead, so you can see where it happens.

53D and K-dimensional arrays

An array with K indices, a[d1][d2]…[dK], is still one straight block of memory. The last index changes fastest (row-major order). The address of an element is base + (i1·s1 + i2·s2 + … + iK·sK) × size, where each stride s is the product of all the dimension sizes after it.

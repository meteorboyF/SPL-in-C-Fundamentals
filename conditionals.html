Conditionals

A program becomes interesting when it can choose what to do. This page covers every form of choice in C: if, else, else-if ladders, nested ifs, && || !, the ternary operator and switch. Every visualiser has a Decisions tab that lists each check with its real values, and try: buttons that re-run the program with inputs that take the other branches.

★How to write any conditional problem

The case table
  1. List every outcome the program can print (positive / negative / zero …).
  2. Write one condition per outcome, and pick one test input for each outcome before coding.
  3. Order them: special and most specific cases first (origin before axis, “both” before “either”, the narrowest range first). The else takes whatever is left.
  4. Run every test input. Every branch should run at least once.

1if and if-else

The condition is any expression: 0 means false, anything else means true. Comparisons (== != < > <= >=) give 1 or 0.

2else-if ladders: order matters

C checks the conditions top to bottom and runs only the first branch whose condition is true, skipping the rest. So every later branch can assume that all the earlier conditions were false. That is why each range test below only needs one comparison.

6Bugs to recognise on sight

= instead of ==
if (x = 5) assigns 5 and is always true. Some people write if (5 == x) so that this typo becomes a compile error.
Stray semicolon
if (x > 0); ends the if with an empty statement. The block below then always runs.
Chained comparisons
1 < x < 5 means (1 < x) < 5, which is 0 or 1 compared with 5, so it is always true. Write x > 1 && x < 5.
Comparing doubles with ==
0.1 + 0.2 == 0.3 is false. Compare with a tolerance: fabs(a - b) < 1e-9.
Wrong order in a ladder
A wide test (x >= 10) placed before a narrow one (x >= 30) makes the narrow branch unreachable.
Missing braces
Without { } only one statement belongs to the if. A second, indented line runs every time.
